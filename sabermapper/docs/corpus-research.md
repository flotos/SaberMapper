# Corpus and research tools

These modules implement a local research pipeline. They do not contain a downloaded corpus, reviewed phrase pool, current player calibration, or trained preference model. The saved player snapshots are historical evidence through March 2025. Do not treat rank, votes, score accuracy, or synthetic labels as a quality or enjoyment verdict.

## Exact-version ingestion

`CorpusStore(root)` keeps a SQLite manifest and content-addressed ZIP archives under the chosen root. Import a lawful local archive with `import_archive(zip_bytes, version_hash=<40 hex BeatSaver version hash>, provenance={...})`, then call `process_maps(version_hash, song_family_id=...)` for normalized maps and phrase records. Processing follows only `Standard` difficulty files declared by `Info.dat`, excludes 90/360 charts, and stores per-file failures in SQLite; `processed(version_hash)` resumes inspection without reparsing. It uses the declared BPM but does not blindly apply a legacy song offset to native note timing. `fetch_exact(hash)` uses BeatSaver's documented `GET /maps/hash/{hash}`, selects only a matching version from the response, downloads its declared ZIP over approved BeatSaver HTTPS hosts, and checks the game-style Info-plus-difficulties content hash before accepting it. It has bounded response size, timeouts, retry/backoff for transient errors, a cache check, and explicit missing/failed manifest status. [BeatSaver's live Swagger](https://api.beatsaver.com/docs/) documents the hash endpoint; its metadata was verified during implementation. Network fetch is an explicit user action, never background discovery.

The ZIP validator rejects traversal paths, case-folded duplicate names, symlinks, encryption, corrupt CRCs, excessive counts/sizes, and extreme compression. Map JSON is read in memory without extracting untrusted paths. The manifest records exact version hash, map ID when known, source URL, archive digest/byte size, expanded and audio byte counts, requested audio-retention policy, status, and provenance. Raw ZIPs remain until `discard_archive_after_processing` is explicitly called after successful persisted normalization; it refuses protected audio and shared archive references. The retained normalized JSON still includes all parsed notes and provenance. `corpus_report(store.rows())` reconciles count and measured bytes. A failed fetch raises a specific error and can be retried; it does not silently substitute another version. `discover_maps` supports bounded metadata-only pages; `select_corpus_seeds` applies explicit cohort quotas and mod exclusions. `seeds_from_candidate_snapshot` converts the saved 12-candidate metadata shortlist into unreviewed seeds. `ingest_seeds` enforces item and new-byte budgets over an explicit list, resumes cached archives, and returns measured time and failures. `coverage_report` reconciles cohort status before expansion.

The local importer accepts a claimed BeatSaver version hash with its provenance. It cannot independently prove that an arbitrary offline ZIP belongs to that BeatSaver version; users should verify against trusted metadata before marking a real seed as resolved. A real manifest should include the exact difficulty, mapper, source hash/URL, cohort purpose, permitted use, mods, and missing-version status. The current starter set is metadata-only and contains Noodle Hard maps that should be excluded from vanilla gameplay learning.

## Patterns, retrieval, and labels

`extract_patterns(map_ir, version_hash=..., difficulty=..., song_family_id=...)` makes deterministic four-beat windows by default, preserving nearby entry/exit notes, rhythm intervals, source beat ranges, BPM, note density, and the shared movement model's local-window metrics. It keeps `song_family_id` for leakage control separate from `motif_family_id` for note-shape grouping. `group_patterns` merges exact and horizontally mirrored note shapes; `repetition_report` counts repeated windows. `pattern_distance` exposes rhythm, placement, hand, direction, and note-count components; bounded `near_matches` returns pairs for human inspection. These are transparent pilot features, not a learned similarity or quality score. `retrieve_patterns` ranks simple BPM/NPS/length proximity, limits to one example per motif family, and can exclude forbidden source versions or held-out song families. Empty results mean the assistant should author a new constrained phrase or inspect a broader source pool, not copy an evaluation song.

`validate_label` keeps structural, timing, readability, flow, difficulty fit, variation, and personal enjoyment dimensions separate. Every label records rater, origin (`human`, `assistant_proposed`, or `synthetic`), family, and time spent; human enjoyment labels require a feedback reference. Ties and unknowns remain explicit. The optional `train_pairwise(..., dimension=...)` uses only human pairwise judgments from allowed **song** families for one dimension, returns `no_go` when fewer than 20 balanced examples exist, and never auto-promotes a fitted model. `evaluate_ranker` compares it with a fixed density baseline on held-out song families and returns a promotion decision only when the preregistered count and improvement threshold are met. Its four density/length features are a feasibility baseline; it cannot establish movement quality. Keep quality and enjoyment models separate.

## Split and evaluation protocol

`SplitRegistry(path)` assigns stable train/validation/test families from an explicit family ID or exact version, with audio-hash aliases. Conflicting family aliases are quarantined for manual resolution. `mark_development(version_hashes, reason=...)` reserves inspected or pilot material for training and tuning and records any earlier validation/test membership as retired. `freeze(records, path)` saves concrete membership, retirement records, and a manifest digest. Do not randomly split phrases from the same song or map version. When an alias merge crosses splits, retire the contaminated evaluation set and freeze a new release. `evaluation_report` rejects direct family leakage and reports pairwise accuracy per cohort.

Freeze rules and thresholds before tuning. Use separate suites for parser correctness, timing anchors, motif similarity, quality/preference ranking, and end-to-end playtests. Record reference reviewers, dates, false positives on intentional technical mapping, retrieval relevance/diversity, and one player's replay choice. This repository currently has no held-out human evaluation set; no model or corpus quality gate can be claimed.

## Historical calibration

`summarize_scores` computes the saved ScoreSaber cohort with ranked, Standard, positive stars, no modifiers, and positive max score. The included snapshot reproduces nine results since 2024 with about 7.43 mean stars and 80.50% mean base-score accuracy. Those are old saved results, not all attempts or current taste. `player_profile` keeps explicit liked/disliked references and user overrides separate. A current calibration still needs named positive and negative sections, comfort/challenge playtests, target movement/rhythm ranges, and the user's actual review-time budget.

## Current measured local pass

On 2026-09-22 the saved candidate metadata was filtered to ten non-Noodle/Mapping Extensions core versions. Exact-hash requests downloaded 78,154,290 ZIP bytes in total; every content hash matched its requested version. A second [100-version metadata manifest](../workspace/corpus/pilot-seed-manifest.json) added 90 versions with quotas of 23 ranked tech, 22 curated, 23 rhythm contrast, and 22 speed contrast. It spans eight upload years (2019–2026, 8–14 maps per year) and 83 proposed mappers. The first additional pass accepted 63 archives before its 500 MB ceiling; a bounded recovery pass restored stale exact versions and accepted 24 more. Three v4 Info 4.0.1 versions still fail a strict BeatSaver/game-style content-hash comparison. They remain explicit failures; no version substitution was made. The [ingest reports](../workspace/corpus/pilot-ingest-report.json) and [audit](../workspace/corpus/pilot-audit.json) retain exact hashes, cohort coverage, and reasons.

The 97 accepted archives total 835,287,150 ZIP bytes, about 8.61 MB per accepted map, suggesting roughly 8.61 GB of ZIP downloads for 1,000 similarly sized maps. This is an extrapolation from a biased pilot, not a committed storage budget. The frozen parser produced 30,733 four-beat windows and 21,785 exact/mirrored motif groups without parsing failure. All 97 versions now retain raw map JSON, its canonical digest, normalized data, and parser/movement/config fingerprints. Cleaned non-calibration ZIPs can be reprocessed from raw JSON after code changes; only the ten protected calibration archives remain on disk (78,154,290 bytes). The [current catalog](../workspace/corpus/patterns.json), [processing report](../workspace/corpus/processing-report.json), and [development manifest](../workspace/corpus/development-manifest.json) retain the artifacts. The 97 pilot families are explicitly development material; 30 initial deterministic validation/test memberships were retired. No archive or score was marked human reviewed, no preference labels were supplied, and the development manifest is not a held-out evaluation release.

The full catalog is large. `CorpusStore.rows()` returns compact manifest columns by default; `rows(include_processing=True)` opts into large processing/provenance JSON. `library_summary(limit=100)` reads the small [library index](../workspace/corpus/library-index.json), including source fingerprints and a stale flag, without deserializing the full catalog. `valid_processed(hash)` returns only a current, non-quarantined version for targeted retrieval. Processing writes atomically under a local workspace lock; a concurrent attempt may report the workspace busy rather than merging two partial catalogs.
