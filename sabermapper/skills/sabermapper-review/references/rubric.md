# Review rubric

Record: source artifact SHA-256, game/editor build if played, beat range, section ID, observation, severity, evidence, intended complexity, change requested, and before/after result.

Treat invalid fields, same-cell overlaps, `hidden_note` stacks (a note too soon behind another in its cell), missing assets, and demonstrated timing drift as defects. Treat parity resets, high angular motion, other center vision blocks, dense repetition, NJS, walls, bombs, and lighting as contextual review items. Compare the phrase against its musical layer, setup and recovery; deliberate technical complexity may be desirable. Never claim enjoyment from note count, validator output, or a static preview.

For a one-song pilot, compare the original map, one scoped revision, and a simple baseline using the same exact audio and timing inputs. Keep the human source map hidden during authoring. Ask the intended player whether each version is readable, expressive, tiring, interesting, and replay-worthy; record elapsed editing/review time and failures as well as improvements. A single rater supports a personal decision, not a population claim.
